Quick start

git clone https://github.com/namandhakad712/drape.git
cd drape
python analysis/run_all.py

That is the whole thing. It runs six analysis scripts, writes their output to results/, then asserts the floor check. If the exact generating program does not score 0.0000%, it exits non-zero and tells you not to trust the numbers above it.

There is nothing to install. No requirements.txt, no virtual environment, no build step. If you have a Python interpreter, you have everything.

The floor check

This is the part worth understanding before trusting anything else. Every metric is fed the exact answer — the program that generated the shape — and must return zero. Four bugs in the measurement code were found this way, and all four had made the headline result look stronger than it was.

What a passing run looks like: 

==============================================================================
FLOOR CHECK -- the exact program must score 0.00%
==============================================================================

  spiral (analytic)              0.0000%
  sine wave (analytic)           0.0000%
  circular arc (analytic)        0.0000%
  5-point star (periodic)        0.0000%
  regular zigzag (periodic)      0.0000%
  varying curvature (smooth)     0.0000%
  irregular staircase            0.0000%
  bounded random walk            0.0000%
  aperiodic irregular            0.0000%

  worst floor: 0.0000%  --  PASS

And what run_all.py prints at the end of a successful run: 

  floor check passed: the exact program scores 0.0000%.

If that line is absent, the run failed. run_all.py exits with status 1, so it will also break a CI job — which is the intended behaviour.

Running one analysis at a time

To see the headline finding on its own, without the rest: 

python analysis/degeneracy_sweep.py

Then look for two sections in the output. The first is the verdict table: 

TWO-SIDED ITEM VALIDITY TEST
  n = 200 points | tolerance 5% of diameter | hop tolerance 2%

shape family                 segs       best fake  par    err%   cov%  hops  verdict
--------------------------------------------------------------------------------------
spiral (analytic)             199        poly d=3    8   0.27%   100%    16  DEAD (both)
regular zigzag (periodic)     199   periodic p=12   24   0.00%   100%     1  DEAD (both)
varying curvature (smooth)    199        poly d=2    6  54.51%     1%   186  VALID
...
families surviving BOTH tests: 3 of 9

The second is the scaling test, which is the one result in the work that is not an artefact of a threshold we chose: 

  spiral (analytic)                4 ->     4   x1.0   FLAT   (degenerate)
  sine wave (analytic)            24 ->   199   x8.3   GROWS  (valid)
  regular zigzag (periodic)        4 ->     4   x1.0   FLAT   (degenerate)

FLAT means the same number of parameters draws the shape at N=25 and at N=200. The shape has a name, and a model that knows the name wins at any length.

Regenerating the figures

python analysis/make_figures.py     # writes docs/assets/figures/*.svg

Every figure on this site is generated by that script from the same code paths the analysis uses. Nothing is drawn by hand and nothing is pasted in, so changing the analysis changes the figures. The SVGs are written with newline="\n" so a re-run in a fresh clone is byte-identical rather than showing up as a modified file on Windows.

The figures live under docs/assets/figures/ rather than a separate top-level directory, so a single copy serves both the GitHub README and this site.

Validating this site

The documentation site has its own checker, for the same reason the analysis has a floor check. 

python analysis/check_site.py               # links, anchors, tag balance, alt text
python analysis/check_site.py --selftest    # prove the checks can fail

The first command verifies that every local link resolves, every in-page anchor exists, every tag is balanced, every image has alt text, and every page carries a description, a canonical URL and a favicon. It exits non-zero if anything fails, so it can gate a deploy.

The second is the more interesting one. It copies the site to a temporary directory, injects four faults — a dead page link, a dead anchor, an image with no alt text, and an unclosed tag — and asserts that all four are reported. A check that has never been observed to fail is not evidence that the thing it checks is correct. 

  SELFTEST -- injecting faults into a temporary copy
    dead page link         caught
    dead anchor            caught
    image with no alt      caught
    unclosed tag           caught
    restore                 clean

  all four faults caught, and the restored copy is clean.

Verifying it on your machine

Every script uses fixed seeds and the standard library only, so the output is deterministic. To confirm that for yourself: 

python analysis/run_all.py
git status --short          # results/ should be unmodified

# if git reports modified files but git diff shows nothing, the stat cache is
# stale rather than the content:
git add --renormalize .

The .gitattributes file pins eol=lf for all text, which is what stops a Windows checkout from reporting every file as changed.

shape_degeneracy.py is kept deliberately. It is the first, single-sided version of the test, and its closing recommendation names "irregular staircases" as a valid item family — which the two-sided test later showed is drawn by two absolute hops. It is the record of how the finding was reached, including the mistake.

Using the interpreter

drape/turtle.py is the part of the work that is sound, and it is usable on its own.

Safety

Model output is never executed. Programs are parsed against a whitelist of eight commands and replayed by an interpreter that only ever does arithmetic. If you are building anything that takes a model's output as a drawing instruction, this is the pattern to copy — exec on untrusted input is how you get owned. 

from drape.turtle import parse_program, simulate, to_source

program = """
forward(10)
right(90)
fd(5)
setheading(0)
"""

cmds, errors = parse_program(program, allow_absolute=True)
trace = simulate(cmds)

trace.segments          # [(x0, y0, x1, y1), ...]
trace.escape_hatch_used # True — setheading was used
trace.n_goto, trace.n_setheading
trace.endpoint          # (x, y)
trace.path_length

allow_absolute=False rejects goto and setheading — the condition that would force a model to maintain its own state, if the analysis had not shown that the escape hatch can be reopened by other means. Aliases (fd, rt, pu, setpos, …) normalise to canonical names.

One command per line. Semicolon-separated commands on a single line are rejected; unrecognised lines become errors rather than being guessed at.

Publishing this site

This site is plain HTML and CSS with no build step, served from docs/ on the main branch. To publish your own copy: 

# once, if you have not already authenticated
gh auth login

# create the repository and push
gh repo create drape --public --source=. --remote=origin --push

Then, in the repository on GitHub: Settings → Pages → Source: Deploy from a branch → Branch: main, Folder: /docs → Save. The site appears at https://<username>.github.io/drape/ within a minute or two. The .nojekyll file in docs/ stops Jekyll from trying to process the directory, which would otherwise drop files beginning with an underscore.

All links are relative, so the site works identically at a project path, at a user root, or opened straight off disk.
